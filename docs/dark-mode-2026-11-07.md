# Appearance modes · 7 November 2026

Customer, Analyst and Superadmin open **Appearance** from the bottom-left profile menu or Settings. The supplier portal has an Appearance icon in its invitation header. Choices are **System default**, **Light** and **Dark**.

The `osura-appearance` localStorage key stores only this browser preference. System mode follows `prefers-color-scheme` changes; explicit Light/Dark overrides it. A small head script applies the saved choice before the app paints. Theme changes preserve current assessment state, customer scope and unsaved drafts. Reset demo does not clear the preference. Workflow data still resets on refresh and is never stored in localStorage.

All five shared stylesheets use paired `light-dark()` colors. Original light values and every layout/typography byte were verified unchanged by reversing those color substitutions. Original-color fallback declarations also keep older browsers in Light mode; the appearance control explains when Dark is unsupported. The dark palette covers tables, native inputs, badges and state banners, source panes, review/decision forms, prepared packs, search, profile/dialog surfaces, administration and supplier flows. Risk-chart hues remain consistent across modes. Print forces the light color scheme without changing the saved preference.
